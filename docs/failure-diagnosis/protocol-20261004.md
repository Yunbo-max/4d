# 自然失败诊断：先确认问题，再生成方法

本轮回答：**哪些错误是反复出现的、哪些资产构成反例、简单输出处理能覆盖哪些错误，以及现有证据能排除哪些原因解释？** 不评选十个新方法，不启动 H9 投影方法，也不以8个开发资产宣布一个重要统一问题成立。

代码父版本：`655b55108bb309758a08efa5358e3ad44fd40b6c`；历史证据版本：`81f4f48330aef6d0c00dce9826335a3b1287850e`。本轮依据 research-autopilot 的 `idea-generation.md`、`development-and-execution.md`、`research-quality-bar.md`。当前状态是 baseline failure discovery，Natural Gate 0 未通过，Gate A 未冻结。

## 原始观察及反例

原数据是 Meta 官方 `facebook/actionbench`，revision `2796071cbe6248422fcbeab3101fa9f9886cb7b9`，总体128资产。原cohort按 `sha256(actionmesh-natural-census-20261002-v1:<uid>)` 的排序选前8，生成结果出来前固定。seed42各一次，最前两个资产额外seed43一次。**统计独立单位是资产；10次生成不是10个资产，16帧不是16个独立样本。** 完整UID、完成的实际case目录、历史分数、序列/GT/报告哈希在manifest。

已有shared-frame0对齐、帧0/8/15的Stage-GT报告显示：Stage I未来两帧平均误差比anchor高7/8；Stage II高8/8；Stage II三采样帧严格递增仅3/8；Stage II未来两帧平均误差比Stage I高5/8、低3/8。以上只数符号，不代表任务损害阈值或总体发生率。

应保留的具体反例：bat在8帧明显变差，15帧回落；`000-078_b0b646eb731848f7837ab8257dfc658c`近乎平稳、Stage I未来平均略好于anchor；`000-049_f50b8e5f13e2498c907cbbe20bf7cf95`的Stage II帧15比anchor更好。不能只留下bat等大误差资产。

## 冻结的竞争解释

| 解释 | 可检查的预测 | 排除/限制该解释的观察 | 测试与限制 |
|---|---|---|---|
| E1：普遍随时间累积失真 | shared-anchor CD4D逐帧持续增长 | 误差中途达峰后恢复、末帧好于早期或anchor | 记录全部16帧和下降区间；原3/8已经反驳普遍严格单调的强说法。非单调仍不能排除弱时间影响 |
| E2：主要跟离anchor的姿态变化相关 | 误差峰值跟GT材料点离anchor的变化更一致 | 姿态变化大而误差低、同样变化量对应不同误差 | 固定对照时间与GT departure的Spearman描述；去掉共同frame0。不能用二者相关性的大小给出因果胜负 |
| E3：主要是可平滑的逐帧噪声 | 固定一次平滑同时降低CD-M与几何距离 | 平滑没改善或改善一项却损害另一项；残余仍在大姿态帧 | 一次 `[1,2,1]/4`；无调参、无GT拟合。平滑可以损害动作，原生CD-M也不等于纯速度/动作指标 |
| E4：Stage II普遍破坏已有形状 | 同一anchor transform下Stage II比Stage I差 | 同条件Stage II降低误差的资产/帧 | 复用现有8资产0/8/15配对报告；不能从两种不同对齐的CD差值做因果误差分解 |
| E5：仅仅是不生成动作反而更好 | 静态anchor的CD-M普遍优于native | native优于静态的资产；shape和motion指标反向变化 | 全8资产加2重复seed，静态是诊断参照而非理论误差下界或任务成功方法，不把零动作称为解决问题 |
| E6：上游视频已经改变了物体 | 错误在进入ActionMesh前已存在 | 官方案例中的输入正确、错误第一次出现在后续stage | 已有panda/Wan和mushroom静态anchor记录是应用情境证据；不混入ActionBench统计，也不据此统一归因CFG |

现有时间坐标反转实验只在两个资产完成：CD-M/几何略好，局部加速度误差都变差；它是冻结Stage-I和查询的Stage-II反事实，不能推广为统一修复。seed43两例的方向也不同，且重新生成了anchor；这不是固定anchor的纯噪声对照。

## 本轮三组、同一原生评分

| 组 | 处理 | 作用 |
|---|---|---|
| `native` | 历史缓存序列不改；完整重新评分 | 数值重放资格及16帧误差剖面 |
| `static_anchor` | 复制相同预测frame0至全部16帧 | 检查生成动作相对静态参照到底增加了什么 |
| `temporal_smooth` | 在原固定顶点ID上，对帧1..14施加一次 `v'[t]=(v[t-1]+2v[t]+v[t+1])/4`；帧0与15保持原值 | 检查一次最简单时间滤波能消除的部分和损害的部分 |

每组均保留原topology、完整16帧、相同anchor。两种处理相互独立，不叠加、不选择超参、不按结果挑组。GT只用于评分及条件描述，控制函数只接收预测vertices。这里是已知简单基线的诊断，不是一个新方法贡献。

评分调用已发布的官方 `compute_chamfer_3d_4d`，100000 surface points、10000 ICP points、24初始旋转、200迭代、seed44，正式CD3D/CD4D/CD-M和原生查询/归约不变。保留已记录的CPU RNG设备兼容补丁。源码6文件逐字节哈希固定。

Instrumentation只记录官方geometry函数的返回值、官方ICP矩阵和原生CD-M逐帧贡献。它不替换scalar返回值。逐帧CD3D/CD4D均值必须还原官方scalar；CD-M以相同frame0最近邻约定取贡献，均值须在 `atol=rtol=1e-6` 内还原scalar。CD-M贡献含anchor形状和第一帧匹配误差，不能称作纯对应误差、速度或加速度误差。

CD3D的每帧独立ICP和CD4D的一次anchor ICP是两种官方对齐条件；二者差值不是一个独立物理“漂移分量”。ICP允许各向异性缩放，也不能证明绝对尺度正确。记录每组实际矩阵以审计；由于三组frame0相同，统一矩阵需在 `atol=rtol=1e-6` 内一致。

首先对该case的三个native scalar与历史报告做数值重放：`abs(diff) <= max(1e-6, 1e-4*max(abs(old),abs(new)))`。这是工程重放公差，不是科研成功阈值。不通过就保留结果、停止该case的控制组，第一case失败则停止整个后续扩展。不能调宽公差救结果。

## 判断与下一步约束

主端点是原生CD-M，CD3D和CD4D共同报告，负的 `control-native` 表示距离降低。以seed42八个独立资产逐项配对，报告每个UID的三项delta、完整状态以及完整case receipt。只有三组资格全部通过的case进入配对均值；失败、pending、部分数据不能填0。报告限定为complete-primary-pair均值，不能从成功子集推总体疗效。

没有新增任务成功标签、严重失败阈值、GT拟合方法或自造benchmark。时间/GT条件相关性仅描述本资产的自相关序列，不提供把帧当独立样本的p值。**没有明确任务后果和有意义的失败边界，就维持Natural Gate 0 unresolved。**

| 返回情况 | 下一步 |
|---|---|
| 重放、source、全帧、资源或矩阵资格失败 | 标记INCONCLUSIVE，修复对应资格；保留原命令/日志/数值；不用方法效果解释软件失败 |
| 静态与平滑已覆盖有意义的缺口 | 优先采用简单办法，停止为这部分制造新方法 |
| 不同资产支持不同原因、共同边界不稳定 | 分开报告失败族和反例，保持开发诊断；不要勉强统一 |
| 平滑后仍有一致、可解释且有任务损害的自然残余 | 冻结一个可证伪的原因预测，补资格化低CFG/强输出拟合等该原因的直接简单替代，再生成结构不同假设 |
| 自然残余与强简单替代后仍成立 | 完成功能级邻近工作审查，再冻结候选方法Gate A；在未看过的官方资产上确认 |

未来确认集应先核查全部已查看UID，再按原128资产固定哈希顺序选下一批未看过的UID。确认前保存完整manifest并锁死方法/参数/端点，不能按本轮曲线挑“适合”的新资产；确认集暂未执行或冻结为方法Gate A。

邻近工作记录以原文为准：[ActionMesh](https://arxiv.org/abs/2601.16148) 是当前backbone/评估来源；[PCGrad](https://arxiv.org/abs/2001.06782) 已涉及冲突训练梯度的投影；[APG](https://arxiv.org/abs/2410.02416) 已涉及CFG更新的平行/正交分解及相关控制。H9换了操作位置/向量含义，不足以自动证明功能新颖。本轮没有以这些旧检索替代最终残余机制的完整碰撞审查。

## 资源、运行与回传

复用现有远端环境和现有缓存；不下载权重、不重新生成视频/Stage I、不申请新机器、不训练。串行GPU评分，首case兼作canary，最多10case×3组=30次完整评分。case外层600秒，round5400秒，Torch allocator cap2048MiB、物理free reserve2048MiB；每2秒检查物理free，原生子进程每秒记录显存。allocator cap与整卡实测显存分别报告。外层可以终止**本轮创建**的process group，不终止其他用户进程。超时/OOM/监控缺失保留失败并停止扩展。预算包括校验、存盘和评分，不降点数、不裁帧。
